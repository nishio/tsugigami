# 2026-11-09 nishio: ページの継ぎ目の隙間

Mac 側の Claude Code(grasp-nishio のセッション)経由で届いた。tsugigami の広告動画を作る対話の中での発言(そのまま)。

```
今ページの継ぎ目に隙間が入ってるけど隙間がない方がいいね
```

## 伝えた側(Mac の Claude Code)が添えたこと(参考。一次ソースは上の発言)

- 依頼文の見出しでは「継いだ紙の見え方について」の発言とされていた。
- 公開版(main 305b27d)を headless Chromium(834x1194 @2x、合成の PointerEvent)で動かし、1 ページ目の紙の左のつまみ → 「右に紙を継ぐ」→ view を右へ → 引く、とすると、継いだ右の紙の領域(x ≥ 794)が机の色 #e6e4de のまま紙の色に塗られず、線だけがその上に描かれた、と報告(Mac の ~/tsugigami-promo/out/seam-a.png。こちらからは見られない)。
- iPad 実機では確かめていない。

## こちら(サーバ側の Claude Code)で確かめたこと

- 同じ手順(線を 1 本 → 右に紙を継ぐ → 継いだ紙が見える位置へ自動で横に動く → ctrl+ホイールで引く)を、手元のビルド(Playwright の Chromium と WebKit)と公開版 https://nishio.github.io/tsugigami/ (Chromium)で試した。どれも継いだ右の紙は紙の色に塗られ、継ぎ目に破線、という見え方で、**机の色のまま残る現象は再現しなかった**。
- 引いた絵で目に付く「隙間」は、縦に並んだページの間の 16 px の机の色(`PAGE_GAP`)。

## 伝えた側からの補足(同日、こちらの「どちらの継ぎ目か」の問いへの返事。そのまま)

```
- 西尾の「ページの継ぎ目に隙間」は、あなたの読みどおり、縦に並ぶ A4 の間の 16px の机の色の帯のことと思われます（Mac 側の動画の引いた絵で、1 枚目と 2 枚目の間に帯が見えていた）。こちらを優先してください。
- 「右の紙が机の色のまま」は Mac 側の録画で見えたもので、Mac 側の操作（view を直接書き換えた）が原因の可能性もあります。
```

nishio(この repo のセッションの利用者)の選択は「両方」(縦のページの間の隙間をなくす + 右の紙の件も切り分ける)。

## 右の紙が机の色のまま、の切り分け(サーバ側)

Mac 側から受け取った capture.mjs の `splice` は、`H.openMenu(0)`(つまみを click してメニューを開く)の後に `H.widen(0)` を呼ぶ。`H.widen` はつまみをもう一度 click してから「右に紙を継ぐ」を click するので、2 回目のつまみの click でメニューが閉じ(`menuPage === i` なら `closePageMenu`)、閉じたメニューの「右に紙を継ぐ」は `menuPage = -1` で何もしない。つまり**紙は継がれていない**。overview.png のつまみに「2枚」が出ていないこと、x ≥ 794 の線が机の上に描かれていることと合う。アプリの不具合ではない(再現せず。Mac 側の操作のせい)。

# 2026-11-07 lab のトークンが本体に引き継がれていなかった

nishio との窓口のセッション(ubuntu-2a)から、このセッションへ届いた依頼をそのまま写す。nishio の発言そのものではなく、窓口のセッションが nishio の依頼として書いた文面。

---

西尾さんから依頼です。iPad のノートが一度も GitHub にバックアップされていなかった件を直してください。原因は lab のトークンが本体に引き継がれないことです。
【経緯】西尾さんは lab（?lab=1）の設定画面にトークンを入れて、それで設定が済んだと思っていた。実際には src/lab/index.ts:42-57 が、本体の Store('tsugigami') の meta 'github' が無いときだけ lab の画面で repo/token を入力させ、Store('tsugigami-lab') の 'lab:github' にだけ保存する。そのため本体の自動バックアップは未設定のままで、nishio/tsugigami-notes には notes/ が一度も作られていない（lab の結果は 10/30 に届いている）。トークンの原本はもう手元に無いが、iPad の 'lab:github' には残っているはず。
【やってほしいこと】
1. 本体の起動時に、本体の 'github' が無く、Store('tsugigami-lab') の 'lab:github' があれば「lab の設定（repo 名を表示）で自動バックアップを始めますか？」と尋ね、承諾されたら auto.configure に渡して試す。トークンの値は画面にもログにも出さない。
2. 本体で自動バックアップが未設定のときは、それと分かる表示を常に出す（ノート一覧など）。
3. lab で新しくトークンを入力したときも、本体のバックアップに使うかを尋ねる（または本体側へ書く）。
4. e2e で確かめる（lab の保存領域にだけ設定がある状態 → 本体を開く → 承諾 → commit が飛ぶ。fake の GitHub で）。wiki への file back、push・deploy まで進めてよい（push の許可は設定済み）。
deploy が済んだら、西尾さんが iPad で行う手順（再読み込み → 承諾 → notes/ に commit が増えるのを確かめる）を、西尾さん向けに短く書いてください。
私は ubuntu-2a（西尾さんとの窓口のセッション）です。終わったらこちらにも一言ください。

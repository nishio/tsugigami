# 使用中の版と公開版を照合する

## 決めたこと

ノート一覧の末尾に「使用中」のコミットとビルド日時、公開版との照合結果、確認・更新ボタンを置く。起動時、一覧を開いたとき、オンラインへの復帰、画面への復帰で確認する。「最新版です」には確認時刻を付け、通信失敗や不正な応答のときは確認できないと示す。

実行中の JavaScript に埋め込んだ版と、ネットワークから得た `version.json` を比べる。コミットだけでは同じコミットの再ビルドを区別できないため、ビルド日時まで一致する ID を使う。HTTP のキャッシュを避け、Service Worker もこの URL をキャッシュから返さない。オフライン起動の成功を最新版の根拠にしない。

新版を検出しても描画中の画面を自動で読み直さない。「最新版に更新」を押したときだけ、公開版を再確認し、Service Worker 自身が返す版が一致し有効化されたことを確認してから、書きかけの線を確定し、表示位置・入力記録・保存の列が完了するまで待つ。待機中は背後の描画・ショートカットを止め、戻るボタンで更新を中止できる。中止後に保存が完了しても勝手に再読み込みしない。

## 比べた案

- 更新した Service Worker の有効化を、そのまま画面の更新と見なす案: 開いたままの JavaScript は旧版なので採らない。
- 新版を見つけたら自動でリロードする案: 描画中や保存の再試行中に切り替わるため採らない。
- オフラインキャッシュの一覧を最新版の根拠にする案: 公開サーバへの照合にならないため採らない。

## 確認した範囲

Windows の Chromium / WebKit で、版一致・新版通知・通信失敗・不正な応答・更新時の再確認失敗を確認した。実際の SW を使う更新は Chromium で、配信を A から B に切り替え、旧画面の維持、B の取得、書きかけの線の確定、保存待ち、中止後に遅れて再読み込みしないこと、再試行後の版 B と線の復元を確認した。オフライン時に最新版と表示せず、ノートは起動できることも確認した。iPad の Safari / ホーム画面アプリでの切り替えは未確認。

# 縦に並ぶページの間を紙で埋め、継ぎ目は破線にする

## 経緯

nishio「今ページの継ぎ目に隙間が入ってるけど隙間がない方がいいね」(2026-11-09、広告動画を作る対話の中。Mac 側の Claude Code 経由、[raw](../../raw/2026-11-09_ページの継ぎ目の隙間.md))。それまでは A4 と A4 の間に 16(`PAGE_GAP`)の机の色の帯があり、引いた絵では紙が 1 枚ずつ離れて見えた。[継ぎ紙モデル](../concepts/継ぎ紙モデル.md)の「A4 を縦に継ぎ足して 1 本の帳面にする」と見た目が合っていなかった。

どの継ぎ目のことかは発言だけでは決まらなかった(右へ継いだ紙の継ぎ目、という読みもあった)。伝えた側の補足と nishio の選択で、縦のページの間の帯のこととした。右の紙の件は Mac 側の操作が原因で、アプリの不具合ではなかった(raw に切り分け)。

## 決めたこと

- **ページの間も紙として塗る。** i ページ目の紙は、下に次のページがあれば次のページの上端まで伸ばす(`sheetRect`、[render.ts](../../src/render.ts))。右へ継いだ紙も同じだけ伸びるので、継いだ紙の下端は次のページの上端と一直線にそろう。
- **継ぎ目は細い破線。** 縦の継ぎ目(次のページの上端)は、右へ継いだ紙の継ぎ目と同じ破線にした。上下で幅が違う所は、はみ出した側の縁だけ実線。外周は実線。
- **方眼はページの上端から数える(これまでと同じ位置)。** ページの間まで方眼を伸ばし、継ぎ目に GRID/2 より近い横線だけ引かない。継ぎ目の前後で 1 マスが少し広く(約 24)なる。
- **座標は変えない。** `pageTop(i) = i × (1123 + 16)` のまま。描き方だけの変更なので、保存してある線・IndexedDB・GitHub の repo の形は何も変わらない。

## 却下した案

- **`PAGE_GAP` を 0 にする。** 座標の上でもページを詰める案。i ページ目が 16 × i だけ上へずれるので、既存のノートの線がページに対してずれる(100 ページ目では 1600、1 ページ以上)。線の座標を書き換える移行が要り、repo の形も変わる。見た目の要望に対して大きすぎる。
- **方眼をノート全体で一続きにする(y = n × GRID)。** 継ぎ目の前後の不揃いは消えるが、2 ページ目以降の方眼が 5〜9 ずれ、方眼に合わせて書いた既存のノートの見え方が変わる。
- **継ぎ目に線を引かない。** A4 の区切り(印刷の単位、時間軸の目盛り)が見えなくなる。破線なら隙間には見えない。

## 確度

- ページの間の真ん中が紙の色になること、継いだ紙の下が机の色になることは e2e で確認(`e2e/app.spec.ts`「縦に並ぶページの間は…」)。
- iPad で見てどう感じるか(破線の濃さ、継ぎ目の前後の方眼の不揃いが気になるか)は未確認。

# 同期は後回しにして、バックアップで守る

## 決めたこと

- 端末間の同期は作らない(nishio:「同期は後回しでいい」)。データは iPad のブラウザの中だけ。
- その代わり、全ノートを 1 つの JSON ファイルに**書き出す**機能と、それを**読み込む**機能を用意した。iPad では共有シート経由でファイル アプリなどへ保存できる(Web Share API が使えれば。使えなければ通常のダウンロード)。
- 最後に書き出してから 7 日以上たち、かつ書いた線があると、メニューボタンに赤い点を付ける。
- 初めて線を書いたときに `navigator.storage.persist()` を申請する(ブラウザの判断でデータが消されにくくなる)。結果はノート一覧の「保存の状態」に出る。
- 読み込みはノート単位で「新しいほうを残す」。同じバックアップを 2 回読み込んでも増えない。

## 理由

- 明日から使える状態にするのが目標で、同期は設計も検証も重い(衝突の解決、認証)。
- Safari は、しばらく使われないサイトのデータを消すことがある。ホーム画面に追加した Web アプリは対象外とされるが、**未確認**。いずれにせよ「履歴と Web サイトデータを消去」では消えるので、ユーザ自身が持ち出せる手段が要る。

## 次に考えること

- 同期を作るなら、ストロークが「id 付きで追加・削除・置換されるだけ」という今の構造は、操作ログを送る同期と相性がよい。

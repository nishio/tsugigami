# GitHub の非公開 repo へ自動でバックアップする

## 背景

nishio:「さきにここに書いたものが消えないと信じられることが安心して日常のノートを切り替えるために必要」。

それまでの守りは、iPad の中の IndexedDB と、手動の書き出しだけだった([前の判断](2026-10-27_同期は後回し_バックアップで守る.md))。
- iPad が壊れたり、ホーム画面のアプリを消したりすると、最後に書き出した後の分は消える。
- 書き出しは人が覚えていないと行われない。

## 決めたこと

- 書いたものを **GitHub の非公開 repo へ自動で commit する**。nishio が 3 つの候補から選んだ(GitHub / Firebase / 手動の書き出しを強める)。
  - repo は `nishio/tsugigami-notes`(非公開、2026-10-27 作成)。
  - iPad では fine-grained token(その repo だけ、Contents の Read and write だけ)を設定画面に貼る。
  - トークンは iPad の IndexedDB にだけ置く。
- **いつ送るか**
  - 書いて 20 秒手が止まったとき。
  - 書き続けていても 3 分ごと(ただしペンが紙に触れている間は始めない)。
  - アプリが裏に回るとき、起動したとき、通信が戻ったとき。
  - 失敗したら 1 分後にやり直す。
- **repo の中の形**
  - `notes/<id>/note.json` と、ページごとの `notes/<id>/p0001.json`(1 行に 1 本)。
  - 書いたページだけが変わるので、送る量が小さく、GitHub 上の差分も読める。
  - ノートの一覧は `README.md` に置く。
- **消さない規則**
  - 手元に無いノートのファイルは消さない。空の iPad で同じ repo を設定しても、repo の中身は消えない。
  - 消すのは「手元で完全に削除した」と記録したノートと、手元のノートの空になったページだけ。
  - 消したものも、git の履歴には残る。
- **戻すとき**: 「GitHub から読み込む」で、手元より新しいノートだけを取り込む(ファイルの読み込みと同じ規則)。
- 手動の書き出し・読み込みは、そのまま残す。

## 理由

- **GitHub を選んだ理由(Firebase と比べて)**
  - 履歴が全部残るので、「どの時点にも戻せる」が仕組みとして保証される。
  - サーバを持たない。
  - nishio が日常的に使っている。
- **Firebase について**: Kozaneba と同じ基盤で、将来の同期や画像の置き場にもなる。ただし次の重さがある。
  - プロジェクトを用意する必要がある。
  - ホーム画面アプリでの Google ログインが不安定だという報告がある。
- **書くたびに送らない理由**: 字を書いている間は通信も重い処理もしたくない。手が止まってから送る。
- 手元の保存を強くしても、端末そのものを失う場合は防げない。iPad の外へ自動で逃がす以外に手がない。

## 確かめたこと

- **偽物の GitHub(テスト用)で確かめたこと**
  - 変わったページだけ送る。
  - 手元に無いノートを消さない。
  - 先頭が進んでいたらやり直す。
  - 空の端末に戻せる。
  - 単体テスト 8 件、e2e 4 件。
- **本物の GitHub(`nishio/tsugigami-notes`)で確かめたこと**
  - Chromium と WebKit の両方で、ブラウザから直接書き込めた(CORS)。
  - 空の repo から始められた。
  - 別の端末(空の保存領域)へ読み込めた。
- 実機の iPad では未確認。

# iPad 自身を実験機にする

## 背景

線のガタつきの正体は、書いている最中のライブ層の描き方で縁のアンチエイリアスが潰れることだと分かったが([計測](../findings/線のガタつきの計測.md))、iPad でペンを離した後も残る理由は iPad の Safari でしか確かめられない。Linux の WebKit(Playwright)は CoreGraphics ではないので、描画の問題は再現しない。nishio が「AI が Safari で実験できるようにしたい」と言った([raw](../../raw/2026-10-28_AIがSafariで実験.md))。

## 選択肢

| 案 | 本物の Safari | Pencil | 費用・手間 | 自動 |
|---|---|---|---|---|
| **iPad 自身を実験機にする(採用)** | iPad の Safari そのもの | 本物(人に「いま書いて」と頼める) | なし。iPad でページを開いたままにする | スクリプトを置けば iPad が拾う。人の手順を含められる |
| クラウドの実機(BrowserStack など) | 本物の iPad | 無し(合成イベントだけ) | 有料。アカウント | 完全に自動 |
| Mac の Safari(手元か EC2 Mac) | macOS の Safari(同じ CoreGraphics) | 無し | Mac か、EC2 Mac 約 16 ドル/日 | 完全に自動 |

## 決めたこと

- 本体のアプリを `?lab=1` で開くと実験機になる([src/lab/](../../src/lab/))。別の HTML は作らず、本物のアプリに小さなパネルを足すだけ(lab のコードは `?lab=1` のときだけ動的に読み込む)。
- 実験の受け渡しは、自動バックアップと同じ非公開 repo(`nishio/tsugigami-notes`)を使う。AI が `experiments/queue/<id>.js` を置き、iPad が拾って実行し、`experiments/results/<id>/` に結果(status.json、log.txt、script.js、スクリプトが保存した PNG や JSON)を 1 つの commit で送り、待ち行列から消す。
- lab は別の保存領域(IndexedDB `tsugigami-lab`)を使う。本物のノートには触らない。GitHub の設定は本体の自動バックアップの設定を読んで使う(無ければパネルで入力)。
- スクリプトは「async 関数の本文」で、引数 `lab` から本物のアプリを動かす([api.ts](../../src/lab/api.ts)): 合成のペン入力 `stroke`、表示位置 `view`、画面の撮影 `shot` / 層ごとの `layer`、本物の Pencil の記録 `record`、人への指示 `say` / `ask`、結果の保存 `save`、環境 `env`、線の点列 `strokes`。
- AI 側は [tools/lab.mjs](../../tools/lab.mjs)(`gh` CLI の認証を使う): `queue` / `wait` / `run` / `fetch` / `ls`。結果は `lab-results/<id>/`(git には入れない。残す価値のあるものは `raw/` に写す)。

## 却下した案と理由

- クラウドの実機: 費用がかかり、Pencil が無い。描画の問題は見られるが、書き味は見られない。
- Mac の Safari: nishio の Mac に SSH で入る前提か、EC2 Mac の費用。描画の再現には良いが、iPad の Pencil と画面での確認が結局要る。

## 制約と注意

- **撮れるのはキャンバスの中身で、画面そのものではない。** `shot` は 3 層のキャンバスを `drawImage` で重ねたもの。コンポジタの問題(キャンバスは消えているのに画面に残る、など)は写らない。それを疑うときは人にスクリーンショットを頼む(`ask` で手順を出し、画像は issue に貼ってもらう)。
- **iPad でページを開いたままにする必要がある。** 裏に回ると見張りを止める(`visibilityState`)。
- **スクリプトはページの権限で何でもできる。** 置けるのはトークンを持つ本人(と、その repo に書ける AI)だけ。repo を公開しない。
- 合成のペン入力には合体イベント・予測イベントが付かない。それが要る実験は `record` で本物の入力を記録する。
- 待ち行列の確認は 10 秒おき(`&poll=秒` で変えられる)。

## 使い方

1. iPad の Safari で `https://nishio.github.io/tsugigami/?lab=1` を開く(ホーム画面のアプリとは別)。パネルに「待機中」と出れば準備完了。
2. AI: スクリプトを書いて `node tools/lab.mjs run exp.js`。結果が `lab-results/<id>/` に落ちる。
3. 人の手順を含む実験は、パネルに指示が出て「次へ」を押すまで待つ。

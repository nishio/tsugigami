# 要件

nishio の発言([raw](../raw/2026-10-27_Notability置き換えの要件会話.md)ほか、Sources 参照)から合成したもの。✅ は実装済み(断りがなければ実機未確認)、🔜 は未実装。

## やめたいこと(Notability から離れる理由)

- 起動時にクラウドサービスの案内画面などが出て邪魔。✅ 何も出さず、前回のノートを前回の縦の位置で、fit(紙の幅 = 画面幅)で開く。
- いらない機能が増えてきた。→ 機能を足すときは「nishio がよく使う」と言ったものか、データを守るためのものに限る。

## 紙のかたち

- 無限キャンバスだが、A4 縦がずっと縦に繋がっている形で使っている。✅
- 横幅が足りなく感じることがあるので、任意に横に追加できるとよい。**その箇所だけ右に広がる**イメージ(その行から下が全部広がるのではない)。✅ ページ単位で右へ継ぐ([判断](decisions/2026-10-27_横の継ぎ足しはページ単位.md))。
- 1 次元の縦スクロールで書いていくと、時間軸という暗黙の整理軸ができてよい([縦スクロールの時間軸](concepts/縦スクロールの時間軸.md))。
- 「右にページ追加」と「fit」を紙の左側のメニューにする(2026-11-06)。✅ ページごとの紙の左のつまみ(⋮)から開く([判断](decisions/2026-11-06_紙の左のメニュー.md))
- **fit = 紙の横幅を画面幅に合わせる。通常時はそれ。この状態では縦スクロールで横にずれない**(2026-11-06)。✅ 開いたときは fit、ピンチで外れる。右へ継いだ紙ははみ出す([判断](decisions/2026-11-06_fitを通常の表示にする.md))。issue #3(2026-10-28)の「そもそも通常のモードでキャンバスが左右に少し動くことができるのはおかしい」「指で画面を動かすのは紙をスクロールするときなのでそんな微小な動かしをすることはない」も同じ向き([raw](../raw/2026-10-28_issue3_描き始めのパームリジェクション.md))

## ノートの使い方

- 1 日単位でノートを使い分けるユースケースは想定していない。「~のノート」と日付が出るのは合わない(2026-11-06)。新しいノートの題名は `ノート(2026-11-03~)` の形でよい(nishio)。✅ 新しいノートだけ。既存の題名は書き換えない。一覧にページ数を足した([判断](decisions/2026-11-06_新しいノートの題名.md))

## 指のジェスチャー

- 手のひらで取り消し(undo)されて不快。**ジェスチャーはいらない**(2026-11-06)。✅ 2 本指タップの取り消し・3 本指タップのやり直しを外した([判断](decisions/2026-11-06_指のタップのジェスチャーを外す.md))。取り消し・やり直しは画面のボタンと ⌘Z / ⌘⇧Z。
- 1 本指のスクロールと 2 本指のピンチ(拡縮)まで消すかは、発言からは決まらない。残したうえで nishio に聞く。

## よく使う道具

| 道具 | 状態 |
|---|---|
| 黒ペンでの筆記(メイン) | ✅ |
| 赤・青のペン | ✅ |
| 半透明のマーカー | ✅ 赤・青・緑・黄・薄い灰・濃い灰。乗算で重ね、インクの下に塗る。既定は太([issue #1](decisions/2026-10-27_Notabilityの書き味に合わせる.md)) |
| 見た目を Notability の設定に合わせる(issue #1) | ✅ 筆圧なし・中くらいの太さ・見本から採った配色([判断](decisions/2026-10-27_Notabilityの書き味に合わせる.md)) |
| パスに触れるとパスを消す消しゴム | ✅ |
| ペンとマーカーのアイコンを見分けやすく | 🔶「ペンとマーカーのアイコンが微妙」(2026-11-06)。軸の太さ・線の太さ・今の色で描き分けた。nishio が iPad で見て決める([判断](decisions/2026-11-06_ペンとマーカーのアイコン.md)) |
| 投げ縄選択 | ✅ 点の半分以上が内側の線を選ぶ |
| 拡大縮小・回転・コピー・ペースト | ✅ 切り取り・複製・削除・色変えも |
| 方眼紙モード | ✅ 5mm 方眼、ノートごとに切り替え |
| 手を置いたまま書いても紙が動かない | 🔶 議事録で「拡大縮小のずれが頻発」(2026-10-30)。実機の記録から、同時 3 点以上と pointercancel を手とみなす規則にした([判断](decisions/2026-10-30_手の群れとpointercancelで見分ける.md))。タップの最短時間も記録から決めた(2026-11-07 追記: 2026-11-06 にタップのジェスチャーごと外したので、この規則は今のコードに無い)。記録の再生では直った。実機で確認待ち。issue #3「描き始めのパームでキャンバスが少し動くことがある」(2026-10-28、2026-11-07 時点で open、[raw](../raw/2026-10-28_issue3_描き始めのパームリジェクション.md))も同じ確認待ち |

## 優先度の付け方

- 「明日から Notability の代わりに使える完成度」が目標。新機能より、**書いたものが消えないこと**と**毎日使う道具がそろっていること**を優先する。
- 同期は後回しでよい(nishio 確認済み)。代わりにバックアップの書き出し・読み込みで守る([判断](decisions/2026-10-27_同期は後回し_バックアップで守る.md))。
- **書いたものが消えないと信じられること**(日常のノートを切り替える前提。nishio、2026-10-27)。→ 保存の再試行と、GitHub の非公開 repo への自動バックアップ([判断](decisions/2026-10-27_GitHubの非公開repoへ自動バックアップ.md)、[書いたものを守る層](concepts/書いたものを守る層.md))。✅ 実装、iPad では未確認。2026-11-07、iPad のノートは一度も送られていなかったと分かった(lab に入れた設定が本体に渡っていなかった)。起動時に引き継ぐかを聞き、未設定の間はノート一覧の先頭に出し続けるようにした([判断](decisions/2026-11-07_labの設定を本体のバックアップに引き継ぐ.md))
- Kozaneba との連携: 手書きを Kozaneba で並べ替えたい。画像のままでよい。ただし今すぐではない([Kozaneba との関係](themes/Kozanebaとの関係.md))。
- リポジトリは公開でよい(nishio 確認済み)。ノートのデータはリポジトリに入らない。
